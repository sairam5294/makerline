# Stakeholder update (on request)

A one-page progress note for someone who isn't in the work: a PM or manager, a co-founder, a partner, an investor, early users. Built from the files, not from memory: STATUS, HANDOFF, DECISIONS, IDEAS, METRICS, COSTS. Draft only; the owner sends it (`~~email` draft or `~~chat` after approval).

## Pick the reader first

| Reader | Wants | Leave out |
|---|---|---|
| Manager / PM | status vs plan, risks, decisions needed, dates | implementation detail |
| Partner / investor | progress on the goal, metric trend, what you need from them | internal tooling, unrelated projects |
| Early users | what changed for them, what's coming, how to give feedback | costs, internal risks |
| Engineering collaborator | what's done, open tasks with IDs, blockers, where the docs are | business numbers |

## Format (≤ 200 words, plain words, no hype)

1. **One-line status:** On track / At risk / Off track, and why in one clause.
2. **Since last update:** 3 outcomes, not activity ("5 testers can log expenses offline", not "worked on sync").
3. **Numbers:** the success metric and 1–2 inputs, with last period's value; "not measured yet" is fine.
4. **Risks and blockers:** each with what you're doing about it.
5. **Decisions needed:** each as a question with a recommended answer and a date.
6. **Next:** the 2–3 things before the next update.

## Rules

- Same honesty as the rest of the kit: never "ready" without outside users; estimates labelled; no personal data about users.
- Cite IDs (D-xx, `2611-03`) so the reader can ask for detail; don't paste internal docs.
- Save the sent version as `docs/product/updates/<date>-<reader>.md` so the next update can show the trend.
