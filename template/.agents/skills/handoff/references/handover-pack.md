# Handover pack (end of an engagement, or a new team taking over)

So the client's or employer's team can run without you. Build it from the files; ≤ 1 page index plus links. Tier: client (run the exec-pack redaction check before sending).

| Part | What to include | Source |
|---|---|---|
| **Where things are** | repo(s), docs map, design files, environments, dashboards, who has access | `docs/README.md`, CONTEXT_INDEX |
| **Current state** | what's live, what's in progress, known issues with severity | STATUS, AUDIT, issues |
| **Decisions and why** | the 5–10 decisions that shape the product, with IDs and revisit dates | DECISIONS.md |
| **Open ideas** | Pending and Parked ideas with their evidence and next test | IDEAS.md |
| **How to run it** | setup, deploy, rollback, recurring fixes | SETUP, `docs/RUNBOOK.md`, when-it-breaks |
| **Risks** | open risks and assumptions with expiry dates | ASSUMPTIONS.md, AUDIT |
| **Metrics** | the north-star, guardrails, where to see them, last values | METRICS.md |
| **Contacts by role** | who decides, who builds, who supports (roles only in shared copies) | ENGAGEMENT.md |

Walk through it in a 45-minute session; record their questions and answer them in the pack. Remove your own access when the engagement ends, and say so in the last update.
